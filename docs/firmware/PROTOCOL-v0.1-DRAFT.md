# 两板串口协议 v0.1 草案

状态：未实现、未上板。基于 V4.4 手册的 GRANT/CLOSED/RESULT/FINAL 消息继续定义。这里不是已经稳定的接口，首次开发前需完成测试向量与双方约定。

## 物理与帧格式

- 3.3V UART，拟定115200/8N1；GPIO见硬件基线。相机原图留在BOX，不通过低速UART传整帧。
- 一行一个UTF-8 JSON对象，以LF结束；拟定最大1024字节（含结束符）。数字范围、必填字段、类型和未知版本必须校验。
- 分包累积到完整行再解析；粘包逐行处理。超长消息丢弃至下一个LF并记错，不无限扩大缓存。
- 串口只发协议；调试日志走独立接口。JSON语法正确不等于消息有效。
- 首版JSON Lines不含帧级CRC。必须测试噪声；若需CRC，定义规范化字节范围和版本后双方同步，不让某一端私自添加。

## 会话、序号与授权

- C6每次启动创建新的控制会话；BOX握手后使用该会话。重启后禁止沿用旧许可。
- `v`为协议版本；`session`为控制会话；`batch`为批次ID；`seq`为本会话单调递增动作序号。停止和错误也要能绑定上下文。
- `GRANT`仅授权一次有限动作。相同会话/序号重复到达时返回已有状态，不能再次开闸。序号回退与旧会话拒绝。
- `hold_ms`是开闸到位后的最大保持时间，`lease_ms`是C6接受许可后允许该动作存活的总时限；开闸动作本身也受租约和限位超时约束。两者不能互相替代。
- 接收许可立即启动本地单调计时器；排队过期的许可不得执行。租约参数上限、开关闸时限仍待MG996R实测确定。
- `STOP`优先处理，撤销许可并尝试有限时关闸；无法确认关闸时进入FAULT，不能伪报CLOSED。心跳不能无限延长旧GRANT。

## 消息方向与责任

| 消息 | 方向 | 作用 |
|---|---|---|
| `HELLO` / `READY` | 双向 | 交换启动会话、协议能力、板端/应用版本和就绪状态 |
| `HEARTBEAT` | 双向 | 在线与故障状态；超时策略由状态机使用 |
| `GRANT` | BOX→C6 | 仅当采集与缓存可用时许可一次送料 |
| `ACK` / `NACK` | 接收方→发送方 | 接受或拒绝及原因，不能把ACK当机械到位 |
| `CLOSED` | C6→BOX | 关闸限位确认、动作序号与本地时间信息 |
| `RESULT` | BOX→C6 | 本次候选计数、可靠分类、疑似、拒判和完整性摘要 |
| `WEIGHT` | C6→BOX | 质量、稳定标志、校准版本；暂态不得作为最终质量 |
| `FINAL` | C6→BOX | 停料排空后最终质量与不完整事件，供BOX主屏/存档 |
| `STOP` / `FAULT` | 双向 | 撤销动作/报告异常；C6始终执行本地STOP优先级 |

`RESULT`的图像证据由BOX保存；C6只保存/上传有界摘要与证据索引。`FINAL`不意味着整批视觉结果完整，必须联合双方完成状态判定。

## 实现前必须补全

1. 固定字段表、枚举、计数口径、重复序号缓存大小与批次结束握手；疑似与可靠分类的包含关系必须明确。
2. 明确启动会话生成方式、计时器回绕、心跳超时、最大租约和开关闸时限。
3. 定义BOX复位、C6复位、残流、模型失败、TF满、称重不稳和网络离线时的未完成记录。
4. 建立坏帧、分包、重复许可、迟到消息和STOP并发的主机测试向量，然后真实串口复核。
5. 确认帧校验需求、证据索引格式和结果上传接口。当前没有Taster-Matrix生产API或凭据，不能猜造接口。

不把手册中的120ms/500ms例子当作已经标定的安全时限。
