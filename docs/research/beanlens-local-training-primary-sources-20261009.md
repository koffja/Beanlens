# BeanLens：M5 MacBook Pro 本地训练路线与一手资料

核对日期：2026-10-09。范围为固定槽位、逐颗生豆的外观瑕疵分类。这里是资料核对与实施建议，尚未安装训练环境、下载数据或在用户设备上训练；本次主代理读取到设备为 Apple M5、32GB 内存，实际可用内存、训练速度与运行兼容性仍需实测。

## 建议结论

首选 **固定相机与光源 → 网格定位 → 每格裁出一颗豆 → MobileNetV3-Small 迁移学习 → 人工复核低把握结果 → 确定性统计计数**。EfficientNet-B0 作为第二个对照。先使用 ImageNet 预训练权重，再用用户自己拍摄、专家确认的生豆图片调整分类器。

这条路线适合几天内形成可检验的模型原型。固定槽位已提供位置，第一版无须额外训练目标检测器。一个格子有多颗豆、空格、遮挡或模糊时应先拒绝分类并要求重拍；“模型不确定”应是处理状态，不必当作一个视觉缺陷类别训练。软件计数针对独立 bean_id，同一颗豆翻面、重拍不能增加统计样本数。

## 数据应该怎样准备

先选真正能通过现有相机观察、且能得到专家可靠标签的 4–6 类。例如正常、黑豆、可见虫蛀、破损/切伤、壳豆，以及实际能收集到且定义明确的其他类。酸豆、霉菌损伤等需要分清“可见外观疑似”与已经人工确认的专业标签，不能从模型输出推导气味、内部状态或食品安全结论。一颗豆可能同时有多个瑕疵，第一版可以限定为专家裁决的主类别，并保留其他标签；扩展时再采用多标签分类。

建议目标为每类 100–200 颗独立实物豆，多个批次/来源，并拍摄两面；这是几天原型的数据采集目标，不是保证准确率的最低门槛。稀有瑕疵若只有十几颗，不应通过反复旋转图片宣称样本已经足够。正常豆也应覆盖不同颜色、品种、处理法和批次，避免模型把正常批次差异当瑕疵。

为每张图保存 bean_id、lot_id、capture_session、side/view、expert_label 和来源。先按独立豆、最好按批次划分训练/验证/测试，再做增强。同一豆的正反面、旋转、重拍、同一原图裁剪都必须留在同一分组。小数据可先用约 70/15/15 的分组比例，但应优先保证每类测试有足够独立豆；另留一批从未用于调参的新批次检查泛化。

增强优先小角度旋转、翻转、有限位置变化。颜色是识别信号，强色偏、灰度转换或大幅色彩抖动需要特别谨慎。裁图应把完整豆体加少量背景装进方形画布，避免切掉虫孔或破损边缘。建议先以 224×224 跑基线，再对细小虫孔比较更高分辨率；放大低分辨率原图不会增加细节。

## 四日实施计划

1. **第 1 日：定义和采集。** 固定光源、曝光、白平衡与焦点；人工确认 4–6 类标签，收集独立豆并赋 ID。拍正反面，制作同源分组。用少量图验证每格裁剪、空格与双豆拒绝规则；先不追求自动翻面结构。
2. **第 2 日：本地基线。** 安装原生 arm64 Python 与匹配的 PyTorch/torchvision，确认 MPS。加载 MobileNetV3-Small 权重，替换分类头，先冻结主体训练头，再小学习率解冻末端。以 batch 16/32、224 像素、小规模短训练作为起点；具体批量与轮数按显存、验证曲线调整，不预设“跑满多少轮就成功”。
3. **第 3 日：检查错误与补样。** 与 EfficientNet-B0 对照；看逐类召回率、精确率、混淆矩阵、正常豆误报率，报告自动覆盖率与人工复核率。只从训练来源补样；验证集定阈值，测试集不能用于反复调参。给“疑似缺陷”保留人工复核流程，概率分数不应直接称为经校准的置信度。
4. **第 4 日：完整盲测。** 选未进入训练的新豆/新批次，整盘拍摄、翻面、合并同一豆证据、人工复核、计数、输出批次记录。记录真实每盘时间、换盘时间、网络/本地推理时间和失败率。抽样误差与识别误差分开呈现，模型测试准确率不能直接当成瑕疵率估计精度。

四天的可交付目标是“在限定类型和固定装置条件下运行、能展示真实独立测试结果的原型”，不是完整专业分级仪。若还没收集到足够、可信的实物标签，优先交付人工确认驱动的标注与计数闭环，同时保留 API few-shot 对照；这比用公开图片得到漂亮但不可迁移的准确率更有验证价值。
