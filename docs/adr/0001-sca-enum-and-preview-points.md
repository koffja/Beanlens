# ADR 0001：瑕疵枚举以 SCA 物理性评估表为权威，设备端只出预览计点

- 状态：已接受（2026-10-23）；**当量表已核对确认**（2026-10-24）
- 影响范围：`GREEN_DEFECT_SCAN` 记录的 `defects[]` 枚举与类别归属；设备端屏显计点；固件内规则常量

## 背景

TasterMatrix 对接文档 v0.1 §5.1 定义了 16 个瑕疵协议键（类别一 5 项 / 类别二 11 项），§2 规定计点与等级由平台权威计算，设备只上报 `{key, count}`。实际核对发现三处不一致：

1. 文档把 `fungus`（发霉豆）归为类别二，而 SCA 物理性评估表把它列为**类别一 1:1**——这直接决定 Specialty 资格；
2. 文档含 `elephant_ear`（象耳豆），SCA 表上无此行；
3. 文档把“萎缩”与“未成熟”合并为 `withered`，SCA 表上是「未熟豆 5:1」与「萎凋豆 5:1」两行。

同时公开来源对当量常数存在多套互相矛盾的版本（部分黑 3:1 vs 5:1，轻微虫蛀 5:1 vs 10:1 vs 3:1），任何一套转载都不能作为依据。

## 决策

1. **枚举与当量以 SCA 物理性评估表（350g 样品版）原文为唯一权威**：类别一 6 项、类别二 10 项，共 16 行。当量固定为：

   | 类别一 | 当量 | 类别二 | 当量 |
   |---|---|---|---|
   | 全黑豆 | 1:1 | 局部黑豆 | 3:1 |
   | 全酸豆 | 1:1 | 局部酸豆 | 3:1 |
   | 咖啡干果 | 1:1 | 带壳豆 | 5:1 |
   | 发霉豆 | 1:1 | 漂浮豆 | 5:1 |
   | 异物 | 1:1 | 未熟豆 | 5:1 |
   | 严重虫蛀豆 | 5:1 | 萎凋豆 | 5:1 |
   | | | 贝壳豆 | 5:1 |
   | | | 破碎/破裂豆 | 5:1 |
   | | | 干果皮/壳 | 5:1 |
   | | | 轻微虫蛀豆 | 10:1 |

2. **平台侧枚举需据此修正**（文档尚未冻结，现改零成本）：`fungus` 改为类别一；`elephant_ear` 移除或并入 `shell`；`immature` 与 `withered` 拆为两键；类别计数改为 6 / 10。
3. **设备端计点仅作预览**：屏上显示本机预览计点，标注规则版本串；落库记录的计点、full defect 合计、等级永远由平台按自己的规则版本重算并签章。设备上报体不含任何点值。
4. **过渡期**：当量表以 `sca-provisional` 版本号内置，屏显带“临时规则”角标；平台侧发布冻结版 `sca-v1` 后，双方按验收用例抽 10 组核对一致再撤角标。
5. **权威文件由平台侧持有**（版权与合规语境），BeanLens 只复制其冻结后的常量表，不各自解读手册。

## 后果

- 需要一次契约破坏性变更（枚举类别与键调整），代价是文档升版本 + 平台解析改动；若不改，设备要么上报错误类别，要么在固件里埋一张与权威表不符的映射表。
- 模型 16 类与 SCA 16 行**不是一对一**：`cut` 与 `broken` 合并上报「破碎/破裂豆」；`fade`（褪色豆）SCA 表无对应行，**不上报 16 项**，仅作设备本地额外观察类，计数进 `metadata.quality.fade_count`。
- 屏显点值在过渡期可能与 App 详情卡不同，属于已知且可见的差异，靠角标与验收用例管理，不视为缺陷。
