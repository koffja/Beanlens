# ADR 0002：双摄配对用时间戳+轨迹，豆粒总数不依赖模型

- 状态：已接受（2026-10-23）
- 影响范围：采集管线、track 配对逻辑、计数分母口径、数据契约 `bean_count_total` 字段

## 背景

BOX 有 CSI1 + CSI2 两路并行接口，但硬件设计明确"双路不等于硬同步曝光"，BRINGUP 要求"不把两路当作硬同步"。单槽连续入料下豆子下落速度极快（十几毫秒量级），同一颗豆在前摄与后摄的成像时刻必然有微秒级差。如果采集方案是"双路连续 + 逐帧全量推理"，K230D 的内存/带宽/算力三重不足，且同一豆会检出几十次,去重成本爆炸。

同时数据集 `v1i`（7 类）与 `v2i`（16 类）**只有瑕疵类、无正常豆类**，模型只能给瑕疵框。如果"豆粒总数"来自检测框数，那 300 颗豆里只有 8 颗瑕疵就会显示"豆粒总数 8"，瑕疵率 100%。

## 决策

### 1. 采集方案：双路连续 + 前景触发连拍（B）

- 两路低分辨率常开做前景/运动判断；窗口内出现变化 → 触发该路 **3 帧短曝光连拍**；
- 只在连拍帧上跑检测，避免逐帧推理；
- 3 帧足够挑清晰度（拉普拉斯方差排序），内存可控；
- 快速豆的触发阈值要实测调整，写进 `config/` 不硬编码。

### 2. 配对判据（硬规则）

- 两路各维护 track 列表；
- **只有时间戳差在 `ΔT` 内的前摄 track 与后摄 track 才允许配对**，`ΔT` 初值 = 2 帧间隔（写进配置 `time_pair_tolerance_ms`，实测再调）；
- 一对一：同一 track 不能被两次配对消费；
- 落单的进「配对不明」，计入豆粒总数但不归类，不硬凑。

### 3. 豆粒总数（分母）不依赖模型

```python
豆粒总数 = 配对成功数 + 配对不明数
```

**瑕疵分类**来自 16 类模型对已配对豆的裁剪图做检测/分类，但总数与模型输出解耦。由此还得到自检规则：

```python
assert sum(16 类计数) <= 豆粒总数
```

违反即计数链路有 bug，屏上直接报错、不允许保存入队（v1 无真实上报，P2 对接平台后同样不上报）。

### 4. 数豆手段（分阶段）

- **过渡态**（v1 联调期）：简单前景+轮廓（零模型成本），让固件主干（会话/去重/统计/上报）不被模型问题阻塞；
- **目标态**（v2 量产前）：独立轻量"豆/非豆"二类检测模型（训练量小、复用现有标注流程）。

## 后果

- 配对率成为关键质量指标：**配对不明 / 豆粒总数 > 20%** 提示"豆路对准或光照异常"；
- 正常豆数 = 豆粒总数 − 瑕疵豆总数 − 配对不明，来自已知三项差值，不靠模型；
- 3 帧/路 × 双摄 × 全分辨率的内存占用须按 K230D 规格再算一遍，若不够才降到单摄或减帧数；
- 轻量数豆模型的训练与集成不阻断 P1 固件，但 P2 发布前必须完成。
