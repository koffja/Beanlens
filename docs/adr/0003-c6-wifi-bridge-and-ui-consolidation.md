# ADR 0003：C6 作网络桥，交互统一在 BOX 屏

- 状态：已接受（2026-10-23）；**v1 暂不实施 C6 桥，延后评估**（2026-10-24）
- 影响范围：固件分层、UART 协议、配网交互、设备绑定流程、设备侧两板职责

## 背景

K230D BOX 本身**无 WiFi 芯片**（BOM、器件手册、H1/H2/H3 说明均证实）。完整版说明明确把"网络队列"派给 ESP32-C6。用户手上已有 Waveshare C6-LCD-1.47 开发板，带 1.47 寸 LCD，可复用。

## 决策

### 1. C6 作网络桥（A）

```
BOX(CanMV/LVGL/640×480) ↔ UART ↔ C6(ESP-IDF) ↔ WiFi ↔ TasterMatrix API
```

- C6 当哑管道：收 BOX 指令 → HTTP(S) → 返状态/数据；
- **配网交互统一在 BOX 的 640×480 触屏**，C6 只执行"连接 SSID"指令并回执状态；
- C6 的 1.47 寸屏只显示网络状态灯（WiFi/API 可达/配额/令牌状态）；
- 两板通过 §7.2 的 C6 桥协议交互，不是完整的两板串口协议（豆路开闸仍按 `PROTOCOL-v0.1-DRAFT.md`）。

### 2. v1 简化：软键盘配网、纯数字配对码（B + ②）

**配网**

- BOX 屏上弹 LVGL 键盘输 SSID + 密码 → 通过 C6 下发 → 失败原地提示；
- softAP（C6 开热点、手机连、网页填 WiFi）延后到量产阶段评估；
- WiFi 凭据一生只输一次，v1 目标是验证链路而非出货配网体验。

**配对码**

- 只做 **6 位纯数字码**（分段 2-2-2 显示），不做二维码（省 QR 库与渲染调试）；
- 8 位数字保留到 P2（生产现场多机时码空间更安全）。

### 3. 绑定后补传与未绑定扫描（②）

- **未绑定时允许扫描**：记录生成、幂等键生成、进本地队列，屏上标"待绑定后上传"（匿名会话）；
- 绑定后队列自动开始上传；
- 队列满时阻断新扫描并提示，不让匿名会话无限堆积；
- 一台设备同一时刻只能绑一个账号；换绑需先解绑，解绑前队列必须清空（全部已上报），否则提示"有 N 条未上传记录，解绑将丢失归属"并阻止。

## 后果

- 多一块板的固件（C6 端 ESP-IDF）与一条 UART 协议（§7.2 C6 桥协议，独立于豆路控制协议）；
- 两板版本要一起管：BOX 固件 + C6 固件 + 两板协议版本三元组；
- BOX 固件不含任何网络栈（`import network` 调用也不需要），所有联网逻辑在 C6；
- BOX 与 C6 任一板重启/掉电都要能恢复：配对状态、令牌、队列在 BOX 侧持久化（TF 卡），C6 只作短期状态缓存与管道。

## v1 实施状态

**v1 暂不实施 C6 桥与网络上报功能**（2026-10-24 决策）。理由：
- v1 聚焦固件主干验证（会话管理、队列持久化、断电恢复、双摄配对、计数规则）；
- C6 桥涉及 ESP-IDF 固件开发、UART 协议调试、WiFi/HTTPS 适配，投入产出比待评估；
- 队列管理与幂等机制可先在本地验证，不依赖实际网络上报。

**延后方案**：P2 重新评估 C6 桥的必要性与实施优先级，或探索替代方案（如 USB 转发、预置 WiFi 模块等）。本 ADR 保留作为设计参考，但 v1 不执行。
