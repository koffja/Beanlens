# ADR 0005：v1 简化——无批次、无证据图、纯数字计数、屏显极简

- 状态：已接受（2026-10-23）
- 影响范围：v1 交付范围、平台侧端点依赖、固件功能边界、UI 复杂度

## 背景

当前处于"比赛简化验证最重要的阶段"。批次关联需要平台先交付 `/api/device/lots` 端点、需要板上列表页与错误降级设计；证据图需要同步裁图+落盘、多一条上传管线、队列要按图片容量阈值管理；实时相机预览要调 CanMV `Display` 与 sensor 流共存。这些都是"验证链路通畅"之外的额外工程。

## 决策

### 1. v1 一律散测，不做批次关联（B）

- 不做批次选择页、不拉 `/api/device/lots`；
- `form_config.sample_ids` 用 `BL-LOCAL-xxxx` 本地占位（xxxx 为 4 位数字递增序号）；
- `metadata.lot_id` 整字段省略；
- 批次关联整个延后到 P2，平台侧 `/api/device/lots` 端点也可相应后排。

### 2. v1 无证据图（A）

- `metadata.evidence_images` 整字段省略；
- 队列简化为"只存 JSON，无需图片容量阈值"；
- 固件不需要裁图、判清晰度、保存图片、多一条上传管线；
- 买家审计"你说有 2 颗全黑豆，图呢？"在 v1 无答案——这是已知代价，P2 补。

### 3. 屏显：纯数字为主 + 诊断页（①纯数字）

**扫描中**

- 豆粒总数、瑕疵豆数、配对不明数 + 大「停止」按钮；
- **无实时相机预览**（避开 `Display` 与 sensor 流共存的管线冲突）。

**诊断页**（从设置进入）

- 手动开关双摄预览（静态抓帧刷新、每秒 2 帧）；
- 仅供装调时看豆路，平时不占资源。

### 4. 配网与配对：v1 暂不实施（C6 桥延后）

- **v1 不做配网**：无 WiFi 连接、无 C6 桥、无 softAP（ADR 0003 延后）；
- **v1 不做配对**：无配对码显示、无令牌管理（网络功能整体延后）；
- v1 聚焦本地固件主干：会话管理、队列持久化（本地验证）、断电恢复、双摄配对、计数规则。

### 5. 队列本地验证

- v1 队列管理完整实现（入队/状态转换/重试退避/容量阈值/断电恢复）；
- 上报端点用 mock 或本地测试桩，验证队列逻辑正确性；
- 幂等键生成、状态机转换、错误码分类等机制在本地环境完整测试。

## 后果

**简化带来的限制**

- 生产端记录都是散测（`sample_ids` 占位），后续批次聚合功能上线也无历史数据可挂——这是已知代价；
- 买家审计无证据图——v1 只能回答"计数是对的"，P2 补图；
- v1 无网络功能（C6 桥延后）——配网/配对/上报整个链路在本地 mock 环境验证，实际联网延后到 P2。

**简化带来的收益**

- 固件主干（会话/统计/队列/断电恢复）可以在**不依赖平台端点、不依赖网络、不依赖图片管线**的情况下完整验证；
- UI 从 5 页简化到 3 页：① 待机（「开始」） ② 扫描中（3 个数字+「停止」） ③ 结果（16 类列表+「本地保存」「放弃」） ④ 设置（重量、队列、诊断）；
- 开发不被"平台端点就绪"阻塞、不被"C6 固件调试"拖累、不被"证据图 COS 策略"干扰。

**延后到 P2 的清单**

| 项 | 复杂度 | 理由 |
|---|---|---|
| C6 网络桥 | 高 | ESP-IDF 固件 + UART 协议 + WiFi/HTTPS 适配 |
| 配对与上报 | 中 | 依赖平台端点 + 令牌管理 + 实际网络请求 |
| 批次关联 | 中 | 依赖平台端点 + 列表页 + 错误降级 |
| 证据图（一类瑕疵） | 高 | 裁图+清晰度排序+落盘+上传+队列阈值全链路 |
| 二维码配对 | 低 | QR 库 + 渲染，但 v1 不是刚需 |
| softAP 配网 | 中 | C6 AP/STA 切换 + web 服务 + 两板协议 |
| 实时相机预览 | 中 | `Display` 与 sensor 流共存要实测，且生产期不看 |

## 适用范围

本 ADR 只约束 **v1 联调与发布**。P2 规划时重新评估每项的优先级与投入产出比。
